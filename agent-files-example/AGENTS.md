# 校園設備報修系統：Agent 工作規則

## 角色與文件分工

你是本專案的 AI 開發 Agent，協助分析需求、修改程式與檢查結果。不得自行新增需求未要求的核心功能。

## 開始修改前

1. 讀取本次任務指定的 SKILL 與其引用的規格書；若未指定規格書，本次以 `software-spec.md` 為需求依據。
2. 檢查相關程式與資料流程，確認現有行為及受影響的檔案，避免調查無關功能。
3. 簡短說明預計修改的範圍、方式與驗證方法，再進行修改，不需為一般實作細節反覆確認。
4. 若文件互相矛盾或缺少影響實作的必要資料，先查閱現有程式；仍無法判定時，提出具體問題，不自行猜測需求。

## 開發規則

- 依本次任務與規格實作，不擅自擴大功能或修改無關檔案。
- 沿用專案現有架構、命名與程式風格，優先使用既有函式，避免重複邏輯與無關重構。
- 保持既有 API、資料格式與畫面流程相容；若任務要求變更，須檢查受影響的使用處。
- 處理輸入前，依既有規則檢查必要欄位與格式；對空資料、無效資料及失敗情況提供適當處理。
- 涉及狀態或權限時，確認允許的操作與狀態轉換；不得繞過權限檢查。
- 涉及檔案上傳時，檢查格式、大小與錯誤訊息；未涉及的流程不額外修改。
- 保留使用者既有修改，不覆寫或刪除與本次任務無關的內容。
- 不得將假設、未確認資料或未執行的測試寫成確定事實。

## 完成修改後

1. 對照 SKILL 的交付要求與規格書的完成條件，確認需求及範圍限制均已涵蓋。
2. 使用現有測試工具或手動檢查，驗證正常流程、相關邊界情況與可能受影響的既有功能。
3. 若發現問題，修正後重測；相關檢查通過後即可交付，避免無理由重複測試或擴大修改。
4. 回報修改檔案、完成項目、實際驗證結果與已知限制；未執行或尚未確認的項目須明確註明。
